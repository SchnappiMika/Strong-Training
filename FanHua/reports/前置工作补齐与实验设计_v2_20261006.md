# 正式训练前的补齐工作与实验设计 v2

## 当前范围与执行顺序

本轮补齐第 4 步的独立单游戏基线和第 7 步的实验设计。长程双游戏正式训练与正式对照实验继续搁置。已修复共享模型及全部旧结果保留；不会将探索性结果重新命名为正式基线。

1. 固定独立基线条件，生成配置、来源记录和验收清单。
2. 先训练 seed 0 的 Flappy Bird 基线，单独评估其最终检查点。
3. 再从新的随机初始化训练 seed 0 的 Timberman 基线，单独评估。
4. 汇总两款游戏的真实结果，检查训练更新、损失、接口及评估一致性；如出现算法问题，保留原结果，单独记录诊断和修订版本。
5. 完成实验设计审核与预算核对。seed 1、2 的基线用于后续重复性验证，配置已生成，不声称已经执行。
6. 用户明确恢复正式实验、且前置验收通过后，才开放正式配置。当前两个条件均不满足。

训练依旧使用原 WemiEnv 客户端，新增代码、配置、模型和记录全部在 FanHua。微信开发者工具的切换和编译需用户配合；Python 服务监听后才编译，并保持单个游戏窗口。

## 第 4 步：独立单游戏基线

本次基线指「相同核心算法仅学习一个游戏」，用于与双游戏持续学习比较；它不是新训练的 PPO，也不是直接使用旧 PPO 的成绩。算法沿用当前 PyTorch 潜在动作 SAC、CQL 与有效完整轨迹 MC 校准实现，不把工程实现称为论文的严格复现。

| 条件 | Flappy Bird 基线 | Timberman 基线 |
|---|---|---|
| 初始化 | 新随机初始化 | 另一份新随机初始化 |
| 训练任务 | 仅 Flappy Bird | 仅 Timberman |
| 外部模型、离线数据 | 不使用 | 不使用 |
| 额外行为约束与输入聚焦 | 关闭 | 关闭 |
| 网络与优化器 | 共享代码，隐藏层 64、潜在动作 2 维、Adam | 相同 |
| 交互预算 | 40000 步，单个阶段 | 40000 步，单个阶段 |
| 更新策略 | 预热 512 步；满足表示和经验条件后每交互步最多更新一次 | 相同 |
| 表示预热 | 500 次更新；要求两种动作覆盖 | 相同 |
| 学习率、折扣 | 0.0003、0.99 | 相同 |
| 当前经验池容量 | 50000 | 50000 |
| 跨任务历史回放 | 关闭；只有一个任务 | 关闭；只有一个任务 |
| CQL 权重、校准 | 0.1、开启 | 相同 |
| 训练单局上限 | 3000 步 | 3000 步 |
| 阶段短程诊断 | 20 局，每局上限 300 步 | 相同 |
| 最终独立评估 | 另起进程，20 局，每局上限 3000 步 | 相同 |

正式共享配置按 Flappy Bird → Timberman → Flappy Bird → Timberman，每阶段 20000 步，因此每款游戏也累计 40000 步。单游戏与共享模型的总交互预算分别为 40000 和 80000；比较时明确每游戏预算和总预算，不混淆两者。完整回合的长度不同会影响实际更新次数，必须使用日志中的真实计数，不能声称所有实验梯度更新次数严格相同。

基线训练只执行当前游戏；未使用另一个游戏的轨迹、共享模型权重或老师输出。恢复基线时也检查其他游戏的已有经验，防止误用双游戏检查点。seed 控制 Python、PyTorch 和经验采样；原客户端未开放随机种子，不能控制树枝或管道序列。

旧 Flappy Bird PPO 和旧共享冒烟模型仍是历史参考，不进入本轮独立基线初始化。本轮基线即使成绩较差，也如实保存，不通过替换老师、偷偷延长预算或换模型来制造成功。成绩差时先区分实现错误和算法效果；技术错误修复后使用新版本、新目录重做受影响比较。

## 基线输出与验收

每项训练保存独立实验目录、配置、原始协议日志、逐局记录、每次更新指标、事件记录和 `.pt` 检查点。独立评估保存另一目录，并记录训练检查点 SHA256、参数摘要和更新计数。

验收要求：训练确实完成预算；仅包含目标游戏；损失与梯度有限；保存和恢复正常；最终独立评估完成 20 局；评估前后参数摘要与更新计数一致；引用的检查点仍与评估 SHA256 一致。高分不能替代这些检查，低分也不自动意味着程序实现错误。

成绩报告分别列回报均值、样本标准差、步数、自然终止和预算截断比例。Timberman 额外报告真实得分；Flappy Bird 的协议没有过管分数，不能把奖励称为真实得分。3000 步仍是人为上限，达到上限不代表自然存活极限。

## 第 7 步：正式实验组设计

以下配置全部从随机初始化开始；已修复共享模型只作探索性参考，不用于这些组的共同初始化。否则「关闭指导」仍带有先前指导训练的参数，会污染对照。

| 组 | 校准 | 历史回放 | CQL | 指导约束 | Timberman 输入聚焦 | 用途 |
|---|---|---|---|---|---|---|
| core_full | 开 | 0.25 | 0.1 | 关 | 关 | 核心 Cal-LAICA 风格方法 |
| core_without_calibration | 关 | 0.25 | 0.1 | 关 | 关 | 核心校准贡献 |
| core_without_history | 开 | 0 | 0.1 | 关 | 关 | 核心历史回放贡献 |
| latent_sac | 关 | 0 | 0 | 关 | 关 | 多组件共同移除的潜在 SAC 参考，不能归因于单一组件 |
| guided_focused | 开 | 0.25 | 0.1 | 5 | 开 | 当前工程扩展方法 |
| focused_without_guidance | 开 | 0.25 | 0.1 | 关 | 开 | 与 guided_focused 比较指导贡献 |
| guided_without_focus | 开 | 0.25 | 0.1 | 5 | 关 | 与 guided_focused 比较输入聚焦贡献 |
| guided_focused_without_calibration | 关 | 0.25 | 0.1 | 5 | 开 | 工程扩展下的校准贡献 |
| guided_focused_without_history | 开 | 0 | 0.1 | 5 | 开 | 工程扩展下的回放贡献 |

`core_full` 也对应同时关闭指导和聚焦的组，无需重复创建同配置实验。各组预备 seed 0、1、2；正式共享交互预算和任务顺序相同，每阶段结束短程评估、保存阶段检查点。最终同一检查点必须独立评估两个游戏；阶段模型在另一游戏的评估用于衡量遗忘。评估轨迹不加入训练池。

指导组使用原 Flappy Bird PPO 以及此前共享冒烟训练得到的 Timberman 指导模型。后者本身包含先前双游戏训练的知识，因此该组明确使用外部先验，不能作为「完全无外部知识」的泛化证据。模型来源、SHA256 和额外计算成本独立记账。指导仅作用于训练目标，部署和评估仍执行一个共享 actor。

所有核心消融保持行为约束和输入聚焦关闭；工程扩展消融保持共同老师、损失定义、网络和预算，逐项改变因素。实验使用同种子集合，不代表客户端地图严格配对。无法把旧 PPO 与本轮不同算法的差值直接归因于 Cal-LAICA。

本轮是已知两游戏的持续学习与跨任务能力保留。未见游戏、未见地图参数的泛化需要另设训练／测试划分，不能由这套实验直接证明。

## 正式训练的前置限制

机器可读状态为 `reports/前置工作验收.json`；配置在 `configs/prerequisites_v2`。正式配置有专门角色标记，训练入口会检查前置验收和恢复正式实验的授权状态，任一未满足则在连接客户端前拒绝启动。

本轮已完成 active seed 0、seed 1 的两款单游戏基线训练与独立评估；seed 2 按用户时间要求排除并保留配置记录。33 份配置已完成 SHA256、任务预算、分组差异和指导来源核对，其中 active seed 对应的正式配置为 9 组 × 2 种子 = 18 次，全部仍处于 held 状态。长程双游戏正式实验、正式实验独立评估和最终总结尚未完成。
