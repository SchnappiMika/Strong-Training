# WemiEnv 双游戏算法迁移与验证说明

日期：2026-10-06。

## 1. 本次工程的含义

游戏环境仍是已有 WemiEnv 微信客户端。新增部分是放在 FanHua 内的训练器、协议适配层、PyTorch 网络、经验回放和评估脚本。Flappy Bird 与 Timberman 共用一个 actor、两路 critic 及对应目标网络；任务标签帮助网络区分同一个数值在不同游戏中的含义。它是同一模型在两个已知游戏上的持续学习，尚不构成对未知第三款游戏的零样本泛化证明。

参数以 `checkpoints/latest.pt` 和 `stage_XX.pt` 保存。一个完整检查点包含网络权重、动作原型、优化器内部状态、熵温度、回放池、随机数状态、训练阶段和步数。文件扩展名不是序列化格式或算法的保证：`.pt` 常见于 PyTorch，`.ckpt` 常用来表示 checkpoint；`.checkout` 需要核对同学的实际保存方式。这里明确使用 `torch.save` / `torch.load(weights_only=True)`，不采用不明格式。

## 2. 对照的原作者代码

参考仓库：[Cal-LAICA-Experiments](https://github.com/bailei951/Cal-LAICA-Experiments)，保存的提交为 `35ba6fc167d9f3257a1c12d943600b096e79f6b9`。

| 参考内容 | 本次实现 | 迁移时的处理 |
|---|---|---|
| `cal_laica/agent/SAC.py` 的隐式连续动作策略 | `fanhua/agent.py` 的 tanh Gaussian actor | 增加任务标签，共用参数；潜在动作维数为 2 |
| 双 Q critic、目标网络 | 同文件 `Critic` 与 `Agent.target` | 目标网络从当前 critic 拷贝初始化，使用软更新 |
| `utils/utils.py` 的动作表示学习 | 逆动力学网络 + 每个任务两个原型 | 使用 CE + KL 预热，最近邻映射到原客户端动作 |
| CQL 的随机、当前策略、下一状态策略动作样本 | 三组候选的保守正则项 | 在每条数据的候选动作维度做 logsumexp；候选统一在当前状态评价 |
| Cal-QL 中 `maximum(Q, mc_returns)` | 当前/下一状态策略候选的 Q 下界 | 仅采用真正结束的完整轨迹 MC；截断或断线不提供可信下界 |
| offline/online 回放概率约 0.25/0.75 | 每条样本约 25% 历史、75% 当前 | 历史池按游戏分别保留，多次切换不覆盖所有旧任务 |
| 初始离线 CQL 预训练 | `collect.py` + `pretrain.py` | 先采集真实客户端数据；短程链路验证尚未执行此阶段 |

这是一份参考 Cal-LAICA 机制的跨游戏扩展。原论文研究的是同一任务下动作集合扩展；本次两个游戏都固定为两个动作，状态与动力学随任务切换，因此不能称为原论文实验的原样复现，也不能直接援引论文定理保证本次效果。

### 与参考代码的具体差异

参考代码存在会影响迁移的实现细节，例如历史池在阶段切换时覆盖、目标网络初始化以及候选张量的维度组织。本次保留机制并修正数据组织。CQL 候选数量采用 10、权重候选值 0.1，而不是照搬原代码按重复数 10 放大损失；新的奖励尺度不同，强度需要用短程结果与消融比较决定。

学习当前任务动作原型时冻结另一任务原型，以免旧数据的潜在动作编码失效。每个任务的预热完成后保持其原型固定，后续 SAC 持续更新共享 actor/critic。共享逆动力学网络可以在另一任务预热时继续变化，但旧任务执行动作使用其冻结原型，不依赖旧逆动力学网络的输出。

原论文的动作数量应为 `2^8 = 256`，五组大小为 51、51、51、51、52。之前中文总结的“28”是上标读取错误，已修正。文件名包含 `no_appendix` 不能用于判断 PDF 缺少附录；实际文件有 16 页，附录在第 11–16 页。定理的次线性解释也应保留假设，不应推广为任意跨游戏任务的保证。

## 3. 真实协议和游戏逻辑

| 项目 | Flappy Bird | Timberman |
|---|---|---|
| 客户端 | `WemiEnv/vchat_minigame/vchat_Flappybird` | `WemiEnv/vchat_minigame/vchat_Timberman` |
| 原始观测 | `[bird.by, down_pipe.py, up_pipe.pheight]`，3 项 | 11 棵树的 `(posiDr,x,y)` 加玩家方向，34 项 |
| 网络输入 | 前 3 项除以 600，其余补 0，总长 12 | 11 个树枝方向 + 玩家方向，总长 12 |
| 树枝编码 | 不适用 | `false=-1`，`center=0`，`true=1` |
| 原始动作 | 0 不跳，1 跳 | 0 左侧操作，1 右侧操作，以客户端代码为准 |
| 重置消息 | action=3，restart=true | action=5，restart=true |
| 训练奖励 | 原始客户端奖励除以 100 | 当前分数减上一分数，结束再扣 1 |
| 真正终止 | 客户端 done=true | 客户端 done=true |
| 步数限制 | truncated，保留 TD bootstrap | truncated，保留 TD bootstrap |
| 得分指标 | 协议没有真实过管得分 | reward 本身是累计分数，可记录最终分数 |

Timberman 的旧 Python 文件宣称 616 维观测，与目前客户端实际发送内容不符。渲染坐标在启动早期可以是 null，因此本次只提取方向，坐标不送入网络。累计分数必须转为增量，否则会反复把已有得分当作新奖励。

Timberman 在检查碰撞之后才调整玩家方向；换边可能只换边而不砍树。因此不能假设一次发出“安全侧”的动作就一定能躲过当前碰撞。必须按实际交互观察学习，而不能按旧文档想象动作语义。

两款客户端由实际时间驱动。Flappy Bird 物理更新约 40ms，动作响应约 100ms；Timberman 血量随渲染帧减少。学习和保存检查点会占用时间，可能改变游戏进程。本次把回合结束后的表示预热、更新、保存移到重置之前，减少下一局因停顿受到影响；每步 SAC 仍有计算开销，需要看实际吞吐与表现。原游戏端没有被修改。

## 4. 验证顺序与证据

### 已完成的真实游戏测试

`experiments/20261006_160242_559225_probe_timberman/result.json` 保存 5 局真实 Timberman 随机测试。每局步数为 2、5、3、5、7；分数为 1、3、1、4、5，观测编码长 12，均为客户端真正终止。此测试证明协议可以交互，不证明学习效果。

### 自动验证

`validate.py` 最初的 8 项验证全部通过，随后补充离线预训练、评估不更新参数及停止保存的验证。最新 11 项均通过，证据保存在 `experiments/20261006_165121_048221_verification/verification.json`：

1. 两个游戏的编码和错误游戏拒绝。
2. 累计分数转增量、终止惩罚、步数截断和非法步进。
3. MC 回报数值、截断无校准下界、两游戏历史池和约 25% 历史采样。
4. 校准正则项的数值与梯度，确保被下界替代的候选不产生原候选梯度。
5. 目标网络初始化一致，actor/critic 参数实际更新且损失有限；另一任务原型不变。
6. 完整检查点恢复后权重一致，并且下一次更新的所有指标和最终参数哈希完全一致。
7. 本机真实 WebSocket 握手、消息、关闭与端口复用。
8. 合成环境中的阶段切换、断线保存、恢复续训、输出目录约束与非法配置拒绝。
9. 无历史在线消融组仍可进行离线预训练，两任务数据均保留，4 次更新与检查点保存成功。
10. 阶段内推理评估不改模型哈希或更新计数，正确记录回报与动作次数。
11. 创建 STOP 文件后训练正常停止、保存检查点并消费停止请求。恢复和参数更新测试同时覆盖行为约束权重 5。

其中阶段测试使用合成环境，并故意触发一次断线，所以日志里出现 `Synthetic disconnect` 的异常是预期测试事件；不能把其中回报当作真实游戏结果。首次验证发现，小样本预热可能尚未覆盖两个动作，已改为继续收集到两个动作均出现后才学习表示；若整阶段仍不满足要求则明确报错。

### 正在执行的真实训练验证

运行 `experiments/20261006_161456_139334_timber_first_smoke`：Timberman → Flappy Bird → Timberman → Flappy Bird，各 768 步。这个运行使用随机预热，不包含离线专家预训练。阶段结束会保存模型，然后等待用户编译下一款游戏。阶段完成事实、更新数及分数以该目录的 CSV、status 和检查点为准。

目前前三阶段已经完成：累计 2304 步，Timberman 第一阶段训练最高分 37，返回 Timberman 的第三阶段训练最高分 163；第三阶段末尾有非终止片段，已从完整回合统计中排除。Flappy Bird 第二阶段多数回合为 13 步，仍未显示稳定的良好表现。第一次连接 Flappy Bird 时，重置成功后客户端断开，尚未采集到有效训练步；保留检查点并重新编译后已恢复。原因尚未确定，不能把它归因于算法或某一次操作。

该短程运行由较早版本的训练入口启动，恢复后的 `status.json` 仍保留此前断线的 `error` 字段。当前状态请看 `status`、阶段与步数；不要把旧 error 当成新的运行失败。后续入口已把旧错误移入 `events.jsonl` 并在恢复时清除活动状态的旧错误，同时记录启动、阶段、失败和恢复事件。

四阶段目前已全部完成，累计 3072 个真实交互步、2400 次 SAC 更新，两游戏均完成表示预热。最终当前池有 768 条 Flappy Bird 数据；历史池保存 Flappy Bird 768 条、Timberman 1536 条。

检查最终当前池发现，最后一轮 Flappy Bird 的 768 个动作全部为 0，即一直不跳；最终策略在这些观测上的确定性动作也全部为 0。其潜在均值范围约为 `[-0.94,-0.90]` 与 `[-0.96,-0.96]`，明显偏向负侧原型。这是本次短程实验的失败表现，必须记录，不能宣称双游戏精通。可能涉及先前 Timberman 策略迁移后的偏置、短预算、缺少离线行为预训练及潜在连续策略与实际离散动作映射的价值偏差；具体原因需要离线数据和同预算对照，不能仅凭一个现象确定。

完整回合统计：Timberman 阶段 0 平均训练回报约 2.465，阶段 2 约 7.092；Flappy Bird 阶段 1 约 -1.689，阶段 3 约 -2.021。这些是训练数据均值，含探索，不能替代独立评估或当作精通证据。

### 接下来的改进实验

已经从真实训练检查点导出 1536 条 Timberman 混合策略数据，目录为 `experiments/20261006_163416_742012_export_timberman_training_behavior`，明确标记为随机预热和在线潜在 SAC 混合行为，不能称为专家数据。另启动旧 PPO 的真实 Flappy Bird 采集，目录为 `experiments/20261006_163655_182920_collect_flappybird_legacy-ppo`，每局上限 800 步，共 20 局。采集质量需要实测。此阶段只执行旧权重推理，并不修改旧实验目录或旧 PPO 权重。

采集得到足够用于初步验证的数据后，缩短本次采集预算并停止采集进程，保留 3 局、2400 步的数据，未完成的末尾片段只留在协议日志中。保存的前三局均达到 800 步上限；最初两局回报约 620.630、609.775。`dataset.json` 明确记录预算缩短与保存范围，没有声称完成原定 20 局。

第一次离线实验 `experiments/20261006_164014_242296_offline_pretrain` 使用首局 800 条 Flappy PPO 数据和 1536 条 Timberman 混合策略数据，执行 1000 次 CQL 更新，仍出现 Flappy Bird 一直不跳。在训练数据上动作与行为一致率约 74.75%，这个数值只是多数类预测，不能说明学会跳跃。

针对这一现象，另外建立 `configs/behavior_pretrain_candidate.json`，加入可关闭的行为约束：在 SAC actor loss 上加 `behavior_weight * MSE(策略确定性潜在均值, 回放中的动作表示)`，候选权重为 5。这是本次跨游戏工程的额外扩展，**不是原论文的 Cal-LAICA 原始项**；原配置默认权重为 0，原失败实验保留。它约束策略不要离开实际行为动作区域，但也可能限制超越行为策略，需用游戏评估及权重为 0 的对照检验。

第二次离线实验 `experiments/20261006_164133_399330_offline_pretrain` 使用当时已保存的 1600 条 Flappy PPO 数据和 1536 条 Timberman 数据，执行 3000 次更新。训练数据上的确定性动作一致率：Flappy Bird 92.3125%，Timberman 87.3698%；Flappy 动作计数为 0:1073、1:527，已经不再全部选择 0。这些仍是训练集诊断指标，不是独立游戏效果。正在用真实客户端评估该检查点，两任务都必须重新验证，不能沿用早先模型的 Timberman 成绩。

该新检查点的真实 Flappy Bird 评估已完成：20/20 局达到 300 步上限，无自然终止；平均回报 230.1216、样本标准差 8.3021；总动作 0:4486、1:1514，证实实际交互已经会跳。评估前后更新计数均为 3000，参数哈希均为 `71c03f02d81a14e6a91b56bc75bda77a2f02f70fffa43e8371d9d4436b0e88c3`。证据目录 `experiments/20261006_164310_266052_evaluate_flappybird`。目前正等待/执行同一新检查点的 Timberman 评估。

## 5. 效果、遗忘和“精通”

训练曲线与独立评估分开。评估使用确定性策略，无梯度更新，并检查模型参数哈希和更新计数不变。每个游戏至少 20 局，报告均值、标准差、最大值、步数、真实终止和截断比例，最高一局不能代替稳定能力。

评估同一个检查点在两个游戏的表现，才能说明同一模型掌握两者。评估早期阶段与学习另一游戏后的同游戏平均回报之差，可用于衡量遗忘。两游戏奖励定义不同，不应直接相加或按绝对大小比较。

正式对照采用相同网络、预算、数据和任务顺序，分别禁用校准、禁用历史回放，或同时令 CQL 权重为 0 构成潜在 SAC 对照。此前 Flappy PPO 可以作为已有单游戏表现参考，但不同算法、预算的数据不能伪装成严格对照。

游戏端未提供随机数种子，因此 Python 种子不能控制随机树枝或管道。多训练种子有助于观察稳定性，但不能声称相同客户端地图的严格配对实验。

## 6. 未达预期时怎样处理

| 现象 | 检查 | 处理 |
|---|---|---|
| 没有客户端连接 | 监听端口、是否在监听后编译、调试窗口数 | 重新编译目标游戏；超时后保存并恢复 |
| 观测长度或类型错误 | 实际打开的游戏、protocol.jsonl | 停止本阶段，查清客户端内容，不能盲目补维度 |
| 多窗口或额外消息 | 原协议无 request ID | 关闭多余窗口并重启服务；保留原始协议日志 |
| 损失或梯度不有限 | 奖励尺度、MC、学习率、Q 值 | 报错并保存诊断，检查数据后降低学习率/保守项等 |
| 新游戏不会玩 | 动作顺序、状态信息、奖励增量、预热样本覆盖 | 先修复接口或数据，再增加预算；不靠最高分宣布成功 |
| 旧游戏退步 | 同检查点独立评估、历史实际采样比例 | 与无回放对照比较，调整历史比例及阶段长度 |
| 每步速度变慢 | updates.csv 与 protocol 时间戳、CPU 利用 | 缩小网络/候选数或减少更新频次，并记录对比 |
| 断线或人工停止 | status.json 和 latest.pt | 恢复模型与优化器，重新编译，重开当前游戏一局 |

所有失败和修复也应留下记录，不能删掉不利结果后只展示最好的一次。
